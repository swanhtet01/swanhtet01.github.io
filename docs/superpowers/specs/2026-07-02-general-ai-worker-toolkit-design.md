# General AI Worker Toolkit Design

## Goal

Make SuperMega's AI agents sellable as general-use business tools, not abstract platform promises. The public site should let a buyer pick one worker, understand what source pack to send, see the first proof, and know that every external action stays approval-gated.

## Scope

In scope:
- Public agent template catalog and generated setup kits.
- `/ai-agents/`, `/products/`, `/agent-templates/`, and contact routing generated by `tools/create_public_vercel_output.mjs`.
- Privacy-light behavior monitoring for page views, CTA clicks, template clicks, and form submissions.
- Verifier coverage so the worker shelf, setup kits, and behavior endpoint do not regress.

Out of scope:
- Changing canonical prices in `pricing.json`.
- Claiming autonomous browser/mobile writes without owner approval.
- Touching DeskPOS shared app internals.
- Adding third-party ad trackers.

## Product Shape

The public offer is a General AI Worker Toolkit:
- DeskPOS Quickstart.
- Viber / WhatsApp Business Ledger.
- Inbox & Calendar Operator.
- Daily Intelligence Brief Agent.
- Factory Ops Ledger.
- Data Cleanup & Reporting Agent.
- Document / PDF Intake Ledger.
- CRM Follow-up & Pipeline Assistant.
- Proposal & SOW Builder.

Each worker must show:
- buyer;
- job it handles;
- source inputs;
- first proof;
- outputs;
- approval boundary;
- setup link;
- MMK price hint derived from `pricing.json`.

## Behavior Monitoring

Use first-party, coarse events only. Record event type, page path, selected template, package, UTM fields, referrer, user agent, and IP hint. Do not capture keystrokes, raw form text, source files, or private credentials. If Supabase is configured, write to `supermega_behavior_events`; otherwise return a clear degraded status so the site remains usable.

## Adaptability

The site adapts by making the selected worker persistent through the contact and setup paths:
- template links carry the chosen template;
- contact forms keep UTM and template context;
- events identify which worker gets clicks or starts;
- operator follow-up can prioritize high-intent tools by template, source, and page path.

## Verification

Required evidence:
- generated starter kit index includes all nine workers;
- each worker has JSON, Markdown, detail page, setup page, source inputs, workflow, outputs, and acceptance tests;
- `/ai-agents/` includes the General AI Worker Toolkit shelf and behavior-monitoring copy;
- `/api/behavior-events` exists in Vercel output and exposes a status route;
- public verifier passes;
- production deployment succeeds and live HTTP aliases pass.
