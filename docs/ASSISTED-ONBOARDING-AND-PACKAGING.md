# Assisted onboarding and packaging

18 September 2026. Proposed strategy and implementation queue, not public pricing or completed capability claims. Current primary task owns implementation and review; no additional background agents dispatched.

## One setup, three useful outputs

Ask new/existing business once, then reuse a reviewed business profile across Shop, Website and Ecommerce. Share business identity, approved media and item/service identifiers; keep workspace authorization, product activation and publication separate. No automatic cross-product overwrite. Show source, last review date and a before/after diff for every import; missing facts stay blank.

Existing-business path: owner supplies an owned public URL or approved menu/catalog file → extract bounded content → show original evidence beside proposed fields → flag uncertain prices, OCR, duplicates, language and availability → owner accepts specific changes → apply idempotently to the selected workspace with recovery. Never crawl private customer records or bypass logins. Website text is untrusted data, never agent instructions. Network fetches require HTTPS, public-address checks including redirects, response-size/time limits and no credential forwarding; file intake needs type/size limits and inert parsing. No automatic scraping is implemented by the current setup choice.

New-business path: choose business type → prepare a relevant draft from approved facts → clearly distinguish sample content and unconfirmed prices → review → separately activate/publish. Keep AI assistance behind the scenes; customers approve useful output rather than learn prompts.

## Proposed packaging, not published prices

| Package | Customer value | Boundaries |
| --- | --- | --- |
| Free local | Evaluate supported single-device workflows, local export and recovery | No hosted SLA, shared accounts, managed backups or unlimited AI promise |
| Assisted launch, one-time quote | Reviewed import, template preparation, device/setup handoff and training | Explicit scope, revision allowance, acceptance checklist and exclusions |
| Managed, monthly | Verified multi-user operation, managed recovery, support and approved insights | Sell only once tenant isolation, restores and hosted journeys are proven; named support allowance |
| Optional add-ons | Additional location, catalog migration, content refresh, domain care | Separately scoped; no hidden per-button charges |

Never paywall basic data export, correction, safety or access to the customer's own retained records. Do not promise every incumbent feature in the free tier. Charge for preparation and ongoing operational value, not unverified AI magic. Manual payment recording remains supported independently of an online payment adapter.

## Price decision method

Do not publish a new MMK price yet. Measure per-customer hosting/storage/backup/AI costs, payment-provider fees if any, actual setup/support time, shared overhead and FX exposure. Minimum sustainable monthly price = fully loaded recurring cost / (1 - target gross margin); setup recovery is priced separately. Run opt-in customer interviews with the same scoped offer, not fabricated A/B results. Record quote acceptance, first-value time, support minutes and renewal intent. Do not confuse acceptance intent with paid conversion. Review existing public promises before any price change.

Current reference points: Shopify lists Basic at USD 39/month on its pricing page; annual billing and transaction charges differ. Wix says prices vary by location and final checkout, with domain connection and business capabilities depending on plan. These are reference models, not a Myanmar price recommendation:
- https://www.shopify.com/pricing
- https://help.shopify.com/en/manual/intro-to-shopify/pricing-plans/pricing-overview
- https://www.wix.com/plans
- https://support.wix.com/en/article/pricing-plans-setting-up-payments

Domain delivery: quote registration/renewal separately, retain customer ownership, distinguish included first-year offers from recurring charges, verify DNS/TLS and preserve rollback. Payment setup later: confirm country/provider eligibility, merchant ownership, fees, webhook verification, replay protection and reconciliation; never infer settlement from an uploaded slip.

## Small offerings to validate before creating more products

1. QR menu/service directory using approved Website content—not an unimplemented ordering system.
2. Catalog cleanup and Shop-to-Ecommerce request setup using one reviewed item source.
3. Monthly content/update care, with a defined revision allowance and published-result checks.
4. Shop daily-close review and owner summary derived from reconciled records, not inferred profit claims.

Quality-of-life queue: import previews, missing-field prompts only, preserved drafts, language-aware copy, tablet targets, status/receipt clarity, one next action and recovery. Use real observed users before claiming ease, conversion lift or incumbent superiority. Retain the existing one-writer resource policy; commission a bounded specialist review only for a measured gap.
